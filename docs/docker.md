# Dockerでの実行

公開元からのデータ取得から始める完全な手順は[README](../README.md)の手順1〜7を参照してください。元PCや旧チェックポイントへの依存はありません。

- 対象: Linux／WSL2のシェル、CPU学習。
- ホストのPython・venvは不要。コンテナ内の`/opt/fly-miko-venv`を使います。
- 実行時は`data/`と`runs/`を個別にマウントします。プロジェクト全体を空のフォルダでマウントして、イメージ内の`simulation/`を隠さないでください。
- 準備時は`data/`を書き込み可能にし、学習時は読み取り専用にできます。
- `runs/`は書き込み可能にします。コンテナを削除してもホストに学習結果が残ります。
- `--user "$(id -u):$(id -g)"`でホストのユーザーとしてファイルを作ります。`--init`も指定してください。
- 初回は`--init-from data/reproduction/random-head-bias-02/initial.npz`、再開時は`--resume`です。同時には指定しません。
- 作業フォルダのソースを変更したらイメージをビルドし直してください。ただし既存実行の再開は学習開始時と同じソース・データが必要です。

デモ・動画生成はこのイメージに含めていません。READMEの手順7でホストのNode.jsを利用します。学習コンテナ自体にポート公開は不要です。

Dockerの実ビルドは開発環境で未検証です。ネイティブ環境で確認した範囲は[検証記録](reproduction-validation.md)に記載しています。
