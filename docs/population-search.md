# ランダム初期姿勢2通りによる世代探索

公開CLIは`random-head-bias-02`用の世代探索のみを提供します。目的は引き続き10秒間の頭の中心の高さの積分（m・秒）の最大化で、移動距離は加点しません。

## 初期状態と目的関数

実行seedから身体状態seedを`seed+3000`、`seed+3001`、対応する脳乱数seedを`seed+1000`、`seed+1001`として作り、`config.json`に保存します。全候補・全世代がこの同じ2条件を使います。毎回初期状態を引き直すと計算済み目的関数値と比較できないためです。この2条件への適応を測るもので、未知の初期状態での汎化性能ではありません。

18関節を各可動範囲内の一様分布、身体全体の向きを一様な回転として生成します。速度はゼロ、最下端が床面から1mmになる高さへ平行移動して開始します。首は胴体に対して中立角で、四つん這い用の−1.31rad補正を使いません。出力変換の基準姿勢も通常の中立姿勢とし、左右の肘は0rad、肩・股関節にも四つん這い用の角度を加えません。首は独立した制御関節ではなく、胴体に追従します。肘の初期角度はランダムで、以降は計測値と脳からの指令で動きます。静止からのランダム姿勢であり、速度を含む全物理状態を無制限にランダム化するものではありません。既存の物理モデルは身体同士の自己衝突を扱わないため、部位間の重なりは排除しません。

候補パラメータをθとすると、目的関数は `J(θ) = (R(θ, 初期状態1) + R(θ, 初期状態2)) / 2` です。

## 1世代の10枠

| 枠 | パラメータの選び方 |
| --- | --- |
| 1 | 全世代で最良の候補を保持 |
| 2–5 | 重複を除いた上位候補への小さい変異4個 |
| 6–8 | 重複を除いた上位候補への大きい変異3個 |
| 9–10 | 新しいランダム候補2個 |

親候補は過去最良と前世代から、同じパラメータを除いて最大5種類選びます。小さい変異は親を順番に使い、大きい変異は親をランダム選択します。`子 = 親 + N(0, σ²)`で594パラメータすべてを変異させます。通常のσは小さい変異0.02、大きい変異0.10です。5世代改善がなければ2倍、10世代以上では4倍にし、改善後は通常値に戻します。新しいランダム候補は`N(0, 0.15²)`です。全10候補のパラメータの重複を排除します。

初世代も同じ構成で、初期候補を変異の親に使います。初期候補は従来の初期重みとゼロバイアス、または既存の最良パラメータです。

旧方式の実行も同じ`--resume`で再開できます。脳・身体・目的関数・時間・seed等の評価条件が一致する場合に限り、既存得点とキャッシュを維持し、次世代から新方式に切り替えます。初回切替時に`before-mutation-v2/`へ設定とチェックポイントを保存します。過去世代は当時の方式で復元するため、旧方式の動画用保存も維持されます。履歴に探索方式、変異幅、停滞数、候補の種類数を記録します。

## バイアスの復元

32特徴量を `f` とすると関節出力は `a = tanh(W f + b)` です。学習対象は `W: 18×32 = 576` と `b: 18` の合計 **594パラメータ**です。32特徴量の集約・50msフィルタ・脳特徴ゲイン20は維持します。初期バイアスはゼロですが、新しい候補の生成・選択・保存ではバイアスも学習対象です。

## キャッシュと保存

`runs/training/<実行名>/evaluation-cache/`に各エピソードの値と再生軌跡を圧縮保存します。パラメータ全値、身体・脳seed、時間、タスク、脳データ・感覚接続・身体・計算コードのハッシュをキーに含めます。内容ハッシュも検査し、異なる条件の結果は流用しません。同一候補は並列投入前にまとめ、世代間・再開時とも計算済みエピソードを再実行しません。2条件の片方だけ完了している場合は未計算側のみ実行します。

通常は初世代20エピソード、次世代以降は新規9候補×2条件＝18エピソードです。最良候補の再生もキャッシュから復元するため、動画用の再シミュレーションは不要です。キャッシュには軌跡も含むため容量は世代数に応じて増えます。キャッシュを削除すると再評価が必要になります。

`latest.npz`に前世代10候補・得点・最良候補・乱数状態・履歴を保存します。中断した世代は同じ候補を再生成し、完了済みエピソードを再利用します。`best.json` / `best-second.json`は2条件それぞれの軌跡です。軌跡の`metrics.return`はその1試行の値、`objectiveSummary.return`は2条件平均です。画面の最良得点・学習曲線は平均値を表示します。

## 実行

先にREADMEのデータ準備手順で初期値を復元してください。新規実行（同名の保存先がまだ存在しない場合）:

```bash
npm run train -- --name random-head-bias-02 --init-from data/reproduction/random-head-bias-02/initial.npz --iterations 10 --population 10 --workers 1 --seconds 10
```

既存実行の再開。`--iterations`は到達する総世代数です。

```bash
npm run train -- --name random-head-bias-02 --resume --iterations 20 --population 10 --workers 1 --seconds 10
```

評価条件数は常に2です。評価条件が異なるシナリオの目的関数値を流用しません。

## 動画用の世代別保存

第1〜5世代、および第10・20・30…世代が完了すると、全10候補×初期状態2通りの動作記録を自動保存します。

```text
runs/training/<実行名>/generations/0001/
  manifest.json
  parameters.npz
  candidate-01-state-1.json.gz
  candidate-01-state-2.json.gz
  ...
  candidate-10-state-2.json.gz
```

各圧縮ファイルの`payload.recording`に、初期姿勢、身体形状、20msごとの位置・回転・関節角・感覚入力・脳出力等の再生記録が入ります。`parameters.npz`には10候補すべての594パラメータ・評価値・その時点の最良パラメータ、`manifest.json`には設定・候補の由来・ファイルハッシュが入ります。モデル本体は含みません。ファイルはコピー保存なので、評価キャッシュや最新チェックポイントの更新・削除には依存しません。

世代完了後に保存し、`manifest.json`が存在するフォルダが保存完了です。新しく起動する学習CLIには自動保存を組み込んでいます。すでに動いている学習には次の監視コマンドを併走できます。保存済みチェックポイントの履歴・初期パラメータ・乱数seedから候補を再構成し、候補IDを照合して既存の動作記録をコピーするため、脳・物理シミュレーションは再実行しません。監視が数世代遅れても対象世代を遡って保存します。

```bash
.venv/bin/python -m simulation.generation_archive --name random-head-bias-02 --watch
```

あとから動画化用の通常の再生JSONを取り出す例（第1世代・候補3・初期状態2）:

```bash
.venv/bin/python -m simulation.generation_archive \
  --name random-head-bias-02 --generation 1 --candidate 3 --state 2 \
  --export runs/replays/generation-1-candidate-3-state-2.json
```

これは動作JSONの取り出しで、MP4の生成ではありません。記録の整合性を検査してから出力します。対象外世代のキャッシュも現時点では削除しませんが、独立した世代別保存の保証対象は上記の世代です。公開版は自作の物理形状による再生を使います。

現在の実行は`random-head-bias-02`（`neutral-head-height-v4-bias`）です。旧シナリオはローカルの履歴として保管しています。評価条件が異なるため、旧得点を新実行のキャッシュへ流用しません。
